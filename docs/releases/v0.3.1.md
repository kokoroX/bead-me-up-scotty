# Scotty v0.3.1 — Security fixes and safer editing

This is a security release. **Everyone should update.**

## Security

- **Websites can no longer act on your local Scotty.** Before this release, a web page open in your browser could send requests to Scotty on `localhost` and change your beads, register folders or start the self-updater. A page using DNS rebinding could also read them. Scotty now refuses writes sent from other websites, and only answers browsers that address it as `localhost`, `*.localhost` or an IP address. If you open Scotty through a LAN hostname or a reverse-proxy domain, allow that name with `SCOTTY_ALLOWED_HOSTS=name1,name2` (see the README section "Opening Scotty by a hostname"). The launcher, scripts and other tools that call the API directly are unaffected.
- **Attachments are served sandboxed.** A scripted SVG committed to `.beads/attachments` could run on Scotty's origin when opened from a review link. Attachments now carry a sandboxing Content-Security-Policy and `nosniff`. Images still display inline as before. `attachment://` references can no longer use `.`/`..` segments to point the browser at other URLs.
- **Next.js 16.3.8** fixes upstream advisories in 16.3.4, including a critical one. Also updated: sharp 0.35.5 (librsvg CVE), markdown-it 14.3.2, brace-expansion, source-map-js, postcss-selector-parser, proxy-addr and other development dependencies.

## Fixes and improvements

- **Your git name is now the default human actor**, matching `bd`'s own order: `BEADS_ACTOR`, then git `user.name`, then the OS user. Previously, if your OS login differed from your git name, closing a bead you had claimed from the CLI failed with "assignee is X, actor is Y" (#61). Installs that saved the old OS-user default without choosing it are upgraded automatically. Your existing allowlist is kept, and an actor you saved in Settings is never changed.
- **A stray click no longer throws away unsaved text** (#84). While the New bead dialog or the detail drawer holds an unsaved edit, comment, close reason or gate reason, clicking outside keeps it open and shows a hint. Esc, Cancel and Close still discard deliberately.
- **Mobile navigation:** on narrow screens the sidebar moves behind a ☰ Menu button and opens as a slide-over sheet (#60, #76).
- **App icon:** the browser tab and home-screen icons now show Scotty's logo instead of the default Next.js icon (#74).
- **Docker:** all build stages share the Node slim base image, so native dependencies are installed under the same libc as the runtime (#64, #63).
- **Development:** the committed `AGENTS.md` agent-rules block now matches what `next dev` generates, so starting the dev server no longer leaves a modified file (#70).

Thanks to @rothnic (#60), @arkajyotiadhikary (#74), @Toady00 (#64), @aspiers (#70), and @muresanroland and @guelo for the reports behind #61 and #84.

## Install this release

**Homebrew** (macOS or Linux):

```sh
brew install brendan-appstart/tap/bead-me-up-scotty   # new install
brew upgrade bead-me-up-scotty                        # existing install
```

**From source:** prerequisites are a supported Node.js version (Node 20.9+; Node 22 or newer recommended), npm, and the Beads `bd` CLI for live project data. Without `bd`, Scotty runs with demo data.

```sh
git clone --branch v0.3.1 https://github.com/brendan-appstart/bead-me-up-scotty.git
cd bead-me-up-scotty
npm ci
npm run build
npm run serve
```

Open `http://localhost:3000`. This checks out the release tag. A detached checkout is expected and is supported by the stable updater. The supervised launcher restarts automatically after a successful in-app update.

## Update an existing installation

**Homebrew:** run `brew upgrade bead-me-up-scotty`, then restart `scotty`. Use Homebrew rather than the in-app "Update now" button.

**Existing Git checkout:** use the in-app update notice, or, after committing or stashing local source changes, run from the app's checkout:

```sh
git fetch origin tag v0.3.1
git merge --ff-only 'v0.3.1^{commit}'
npm ci
npm run build
```

Restart Scotty. If Git refuses the fast-forward, keep your work and use a separate release checkout rather than resetting your branch.

**Global copy or source download:** build a fresh checkout of this release using the source steps above, then repeat `npm install -g .` for a global copy, or replace the source installation. Restart Scotty.

**Docker:** rebuild the image from the release source and recreate the container with your existing configuration and mounts. If you open the container by a hostname rather than `localhost` or an IP address, add `-e SCOTTY_ALLOWED_HOSTS=<name>`.

Updating changes Scotty's source and dependencies, not your Beads issue database. Back up your local project data as usual.

## Scope and validation

This is a source release, installed through Homebrew, Git/source or Docker. It does not publish an npm package or a desktop installer. Beads data stays local and is not modified by the release process.

Validation used isolated servers in both editable and read-only modes, intercepted browser fixtures, and disposable test folders. Four new regression scripts cover the security and editing fixes: `test-request-guard`, `test-attachment-hardening`, `test-actor-default` and `test-unsaved-dismiss`. Each was confirmed to fail on the previous build. Every regression script passes in its intended server mode, with one exception: `test-review-links` has a selector that fails intermittently when the Needs You badge shows a count. That test is being fixed in #68, and it passes with the corrected selector. The production build and TypeScript checks pass. Lint reports no errors and one existing navigation warning in `hooks/use-notifications.ts`. `npm audit --omit=dev` still reports 9 advisories (5 high, 4 moderate), all in the `@11ty/eleventy` dependency chain used by the static Publish feature (chokidar, braces, nunjucks, gray-matter/js-yaml). That is the subject of the next dependency update. The Docker image builds and serves the demo project, and the Homebrew formula installs and passes `brew test`.
